> **The append-only ledger of every completed phase.** Moved here from

> [0124](../decisions/0124-progress-live-state-contract.md)). **One rule (ADR
> [0186](../decisions/0186-documentation-consolidation-one-home-per-fact.md) D7): completed
> phases, forever — a completed row never leaves, a missing one breaks the many places that
> point here.** Not-started rows live only in `PROGRESS.md` § Phase Status, never here
> (enforced by `npm run lint:progress` — a completed row in the live file fails the gate and
> must move here, verbatim, in the same change).
>
> Content below was moved **verbatim** except for one mechanical transform, applied
> because this file lives in `docs/progress/`: link prefixes `](docs/progress/` →
> `](`, and `](docs/{decisions,plans,reviews}/` → `](../{decisions,plans,reviews}/`.
> Nothing else was edited. Gate headlines stay in the rows; verbose Build/Tests/QA
> prose for older rows was rotated earlier to
> [phase-status-archive.md](phase-status-archive.md), which remains the archive for
> cell *prose*; this file is the authority for the *rows*.
>
> **Row discipline:** a phase's row arrives here at the §6 Record step of the phase that
> completes it, byte-identical to the row that leaves `PROGRESS.md`. **A row may be EDITED —
> only DELETION is forbidden** (amended 2026-09-04; the former clause banned editing outright
> and forced every correction into a strike-and-correct note). Correct a row in place when a
> fact in it has gone false: `git log -p` / `git blame` on this file is the audit trail, so
> strikethrough is *permitted, never required*. ⚠ **One exception, because the reader cannot
> diff a verdict:** when the edit changes a recorded **outcome** — a gate result, a QA verdict,
> an approval, a pushed/not-pushed claim — say so in the cell with the date, rather than
> silently overwriting what the phase was recorded as having proven. ⛔ Rows are **never
> removed** (ADR 0186 D7) — a missing row breaks the many places that point here.
