# The `npm run lint` gates — why each one exists

> Rotated out of CLAUDE.md §8 on 2026-08-29, rewritten per ADR 0186 D8 on 2026-09-03. `package.json`'s `lint` script is the sole authority on what runs, in what order, with what flags — this file carries rationale and the trap in reading each gate's output, one paragraph per gate, never a check list. Every gate below, the base linter's own scope and policy included, was locked down only after the defect class it now catches had already shipped live. Most self-test their own checkers against a bad and a good fixture on every invocation and refuse outright (exit 2) if a checker cannot fail on the bad one: `lint:client-server-imports`, `lint:progress`, `lint:rules`, `lint:adr-index`, `lint:mojibake`, `lint:service-role-registry`, `lint:registers`, `lint:config-schemas` and `lint:budget-anchor` all do this (⭐ the last two added 2026-09-08 — `lint:config-schemas` was landed with the exit-2 shape and this sentence was not updated with it, so the list understated itself by one **for 48 minutes**; both were re-verified against a planted checker before being added here rather than assumed from the script's header. ⚠ CORRECTED 2026-09-08: that clause read *"for five days"*, which was measured wrong by a factor of ~150 — `6fee08ae` 12:17:44 and `5602830d` 13:05:44 are the same afternoon, and `5602830d` is the *very next commit to touch this file*. ⭐ The finding survives the correction and is why the sentence stays: this list is hand-maintained, nothing gates it, and it did lag. What did NOT lag is R13's actual instruction — `6fee08ae` edited `package.json` and added the `lint:config-schemas` bullet **in the same commit**, so the same-commit rule was honoured and only the exit-2 *list sentence* trailed it. *Two accounts of one event, and the alarming one gets repeated* — say both, and correct the figure without downgrading the finding); `lint:vacuous` and `lint:set-local` run the same shape but exit 1, not 2; `lint:css-vars` and `lint:memberships-door` carry no self-test; `lint:authz-vectors` runs BOTH generators' `--self-test` ahead of their `--check` as of 2026-09-04 (Gate AE4 F-MAJOR-5 — until then the discrimination suites existed and no gate invoked them, so the proof that gate 12 could refuse was manual-only and rotting), and unlike the exit-2 family a self-test failure there simply reds the chain. Nothing gates this file: verify a claim here against `package.json` and the script's own header before trusting it.

- **`eslint --max-warnings=0`** — restores a meaningful base lint after the whole-tree config drifted into linting compiled build output inside agent-team worktrees, burying real findings under noise nobody could act on (ADR 0067). Trap: scope is first-party source only (`src/`, `e2e/`, `*.test.*`) — `.claude/` is permanently excluded, so a red is always application code, and one warning fails the gate exactly like an error. When it reds: fix the finding, prefix an intentionally-unused binding with `_`; never widen scope or relax the threshold to get green.

- **`lint:css-vars`** (`check-tailwind-css-vars.mjs`) — Tailwind v4 dropped the shorthand that turned a bare `[--var]` arbitrary value into a `var()` wrap, so the class now compiles to invalid CSS the browser silently drops, invisible to tsc and to a diff review alike; it has shipped as dead motion utilities and once as a menu running off-screen with no way to reach it. Trap: it scans `e2e/` too, because Tailwind v4 mines it as source, so a class literal inside a comment still mints a dead selector into the bundle. When it reds: rewrite to the `(--x)` or `[var(--x)]` form; don't ignore the file.

- **`lint:memberships-door`** (`check-memberships-door.mjs`) — application code must never write `memberships` or `hospital_affiliations` directly; every grant/revoke goes through a door RPC, because a raw insert/update/delete produces a row indistinguishable from a door-written one, and review does not scale to catching that forever — it already got through once. Trap: it matches the DML verb right after `.from('<table>')`, so `.select()` on the same table is deliberately allowed, not a blind spot — actions often must read what a principal holds before asking the door for anything. When it reds: replace the raw write with the door RPC; never widen the ACL instead.

- **`lint:client-server-imports`** (`check-client-server-imports.mjs --gate`) — a Client Component value-importing from a `server-only` module drags server code into the browser bundle and aborts `next build`, invisible to tsc, eslint and vitest alike because types erase and values don't; it has shipped twice. Trap: a `'use server'` module deliberately terminates the traversal (Server Actions are an RPC seam, not a bundling boundary), and comments are stripped before matching, because more than one module here warns about this exact bug in prose containing the words the detector looks for. When it reds: move the shared value behind a server boundary or split the module; don't just rerun `next build` and assume tsc would have caught it.

- **`lint:vacuous`** (`check-vacuous-assertions.mjs --gate`) — a test whose every assertion sits inside a conditional can finish having asserted nothing and reports the same green as a test that checked the real thing; nothing else in the chain can tell the two apart. Trap: the property enforced is only that some assertion runs unconditionally, not that the test is strong — green is a floor, not a coverage verdict — and the detector self-tests first, so a run that never reaches the real scan is a broken detector, not a clean file. When it reds: move or duplicate the assertion outside the conditional; don't delete the branch to silence it.

- **`lint:set-local`** (`check-migration-set-local.mjs`) — a top-level `SET LOCAL` in a migration has no effect outside a transaction; Postgres only warns and continues, so it passes every local gate while silently no-op'ing a guard meant to protect a data-dependent backfill, invisible on a fresh local reset because the backfill matches nothing there. Trap: the boundary is a watermark, never an allowlist, and must never be advanced — bumping it after a push grandfathers the migration you just wrote instead of the ones already applied, flipping the gate from stricter over time to weaker. When it reds: wrap the GUC and its statements in one `do $$ … $$` block or an explicit `begin`/`commit`; never advance the watermark to pass.

- **`lint:progress`** (`check-progress-doc.mjs`) — PROGRESS.md loads on every session and teammate spawn, and every rule that once kept it small and true lived only in prose; attention lost every time — its own size banner went stale about its own size, a rotation once nearly destroyed follow-up entries whose index lines had no bodies, completed-phase rows kept being paid for by every spawn long after the phase closed. Trap: the size band only warns, so a warning on an otherwise-clean run is not a red; gate 7 and gate 13 now share one link-checking implementation (7 imports it from 13) rather than duplicating it, so a fixture that fools one fools both identically — by design. When it reds: cut the content to its real home (a hub's current-state block, the bug table, the follow-up register, the ADR index) in the same edit; never widen the cap or restore a cut heading.

- **`lint:rules`** (`check-rules-staleness.mjs`) — a standing rule in `.claude/rules/` has no resolution event, so a rule describing a renamed or deleted symbol loads forever with nothing able to contradict it; the keystone is a rule's own `paths:` glob matching zero files, since that glob already exists for loading and costs nothing extra as a staleness probe. Trap: a red because an `anchors:` literal moved is the gate working, not a false positive — fix the rule's text, never loosen the anchor; a `broad:`/`source:` value written as a YAML folded scalar is now parsed correctly rather than read as the literal `>-`/`>` marker, and seeing that marker as the value is itself a red; a repo with no `.claude/rules/` directory reds too, rather than passing vacuously. When it reds: repoint the anchor or retire the rule verbatim to `docs/progress/rules-archive.md`; never delete it outright, never widen `paths:` past its volume bound to dodge the orphan check. ⭐ **Added 2026-09-08 — CRLF is reported as CRLF, first, by name.** A CRLF checkout used to surface here as "no `paths:` globs" / "no `anchors:`" plus byte-cap breaches (+1 byte per line carries a 2011-byte file past the 2048 cap), i.e. the gate blaming each rule's *content* for its own reader's line-ending assumption. That misattribution cost a session: it was recorded as `npm run lint` redding on `main`, with `.claude/` measured byte-identical to `main` to prove it — **both measurements true, the conclusion wrong**, because `.gitattributes`' `* text=auto eol=lf` clean filter normalises CR *on the way in*, so `git hash-object` matches and `git status` is clean while the bytes on disk differ. ⛔ **A claim about a file's CONTENT is not a claim about the BYTES A GATE READS**, and on Windows git cannot show you the difference. The text is now normalised before parsing *and* before the byte cap, so every other finding is about content; CRLF still reds, it is just named.

- **`lint:adr-index`** (`build-adr-index.mjs --check`) — the back-pointer from an amended ADR to the one that amended it is the one fact an ADR cannot record about itself, being written later, by someone else, in a different file; measured once (2026-08-24) that almost none of this tree's amended ADRs carried one by hand, so a session opening the amended one read a superseded rule with nothing able to contradict it. Trap: it also carries a 30-day review timer on a proposed ADR, and that arm reds on the calendar alone, no file touched, once overdue — a nudge to do the review, not a drift bug; a missing `**Amends:**` label is invisible to every gate, only a malformed one (no colon) is caught. When it reds: run `npm run adr:index` after fixing the label, or do the review; never hand-edit `INDEX.md` or backdate the stamp to silence the timer. ⭐ **Added 2026-09-08 — it now resolves link TARGETS, not just numbers.** Before this, the only existence check was over the *number* map: `[0171](./0171-anything-at-all.md)` was green because `0171` exists, and the slug was never looked at — so 14 dangling ADR-to-ADR links sat in the tree while this gate printed `OK`, and a hand audit reading one of the offending lines missed a second broken link on that same line. It reuses `checkLinks` imported from `check-docs-registers.mjs` (one link checker across gates 7, 9 and 13, never two that could disagree) and passes it a **case-exact** `exists` built from real directory listings — ⛔ `existsSync` is case-insensitive on NTFS, so a wrong-case link would be green here and red on a case-sensitive CI. Findings are `--check`-only and deliberately NOT in `hardFindings()`: routing them into the generated `INDEX.md` would surface a broken link first as "INDEX.md is out of date — run `npm run adr:index`", sending the reader to a regeneration that fixes nothing, and would commit a tidy normalised list of the defect — an allowlist in all but name. ⚠ Gates 7 and 13 still use the case-insensitive `exists`; zero wrong-case links exist today (measured), so that is a gap, not debt.

- **`lint:mojibake`** (`check-mojibake.mjs`) — a tool that reads UTF-8 as cp1252 and saves it back re-encodes a multi-byte character into several separate, still-valid UTF-8 characters, and the damage compounds on every repeat; the file stays valid UTF-8 throughout, so there is no bad byte to find and no other gate notices — a grep for the original character misses every affected line, so recorded work reads as if it never happened. Found live 2026-08-24, all pre-existing. Trap: a lead-then-continuation-byte shape is only a candidate — ordinary accented pt-BR text can match it by coincidence — so the real test is that genuine mojibake decodes back to its original character and coincidence doesn't; on Windows the usual vector is a shell round-trip through a cp1252 console. When it reds: re-save the file as UTF-8 with the Edit tool, not a shell redirect.

- **`lint:service-role-registry`** (`check-service-role-registry.mjs`) — the registry documenting every service-role write in `docs/backend-state/authorization-and-audit.md` used to be hand-maintained prose and drifted from the code within a single commit once real writes moved behind a door. Trap: comparison is a multiset, not a set, so a legitimately-duplicated call site (one door called twice for two grants) must appear twice in the registry too — collapsing it to one row reds even though the lists look equal at a glance; the plain call census also undercounts because it only sees a shared wrapper's own inner call, so this script expands that placeholder into the real sites and checks the substitution both ways. When it reds: update the row for the sites that actually changed, keeping duplicates duplicated; never delete a row just to make the count match.

- **`lint:authz-vectors`** (each generator's `--self-test` then its `--check`: `gen-authz-matrix-cells.mjs` ×2, `gen-authz-differential-cells.py` ×2) — the authorization-matrix cells and the differential-oracle cells are both generated from one axes file, and an earlier sibling generator of the same shape had its drift check wired into no gate at all; this closes that gap for both together. THE TRAP, load-bearing: a green `--check` proves only that the generated files still match the axes file — it says nothing about whether the generator's own coverage arms (every catalog permission has a test mapping, every non-legacy role has an approved matrix) exercised anything, because those arms can range over an empty set and pass having checked nothing. Discharging that is what the `--self-test` arms do, and they were chained into this gate on 2026-09-04 (Gate AE4 F-MAJOR-5) after existing for the whole phase as an opt-in nobody's gate ran. Each mutates the real spec ~30 ways and demands a refusal per mutation, then finishes with a discrimination control on the UNMUTATED spec (`caught nothing on the real spec` / `clean on the real spec`) — so a self-test that catches everything because the checker is stuck on refuse reds too. Read those two closing lines, not just the exit code: a self-test whose control line is missing has not proven the checker can pass. When it reds: regenerate with the write form after fixing the axes file or the generator; the JSON-to-database half of the loop is a pgTAP suite's job, not this gate's.

- **`lint:registers`** (`check-docs-registers.mjs && build-features-index.mjs --check`) — every documentation register in this tree that shipped without a gate rotted, so this is that admission rule made concrete: no register or field exists without a check that can red on it, across feature hubs, the bug table, the lessons table, postmortems, the follow-up register and the handoff convention. The `complete` cross-check on a hub is row-grade: a real ledger row, or a review whose verdict line actually reads APPROVED — "NOT APPROVED" and "CHANGES REQUESTED" both red rather than matching on the word "Verdict" alone. THE TRAP: this gate checks presence and resolution, never truth — it knows a closing condition exists, not that it is right, and `PO to rule` is a legal, counted value, not an invisible one; several of its counts (`PO to rule`, `unrated`, `untriaged`, a duplicated register-line paragraph) are ratchets that may only be lowered, so they print on every clean run and are not themselves a red — a rising ratchet on an otherwise-clean run is the thing to chase, and each arm's printed subject count is how you tell it exercised something real rather than an empty population. Its RETIRED arm reds on a living file's citation of a PROGRESS.md section this tree already cut; a code-span or fenced quotation of the old heading is not a citation and is deliberately excluded. (The old CURRENT.md cross-check and the deferred-backlog id comparison were both retired with the files they checked, not weakened — that's why they're gone if you go looking.) When it reds: point the stale reference at the section's real home, add the missing field, or lower a ratchet you've earned; never raise a ratchet's cap to match a rising count. ⭐ **Changed 2026-09-08 (pre-AE5 Batch 6), three ways.** (1) The `complete` cross-check's two regexes could not match the tree's own conventions: `hubHasLedgerRow` rejected a **bold** id (`| **AE4** |` mismatched at the first `*`), and the verdict regex was case-sensitive and admitted only `[\s*]` decoration — so `# ✅ VERDICT: APPROVED`, a real approval, failed twice. Both now tolerate non-letter/non-digit decoration **on both sides of the colon**, which is what makes them safe: `NOT` and `CHANGES REQUESTED` are *letters*, so no amount of decoration can span them, and `>`/`~` stay excluded so a blockquoted or struck-through verdict is still not an approval. It also reads a **bare `## Verdict` heading with the verdict on the next line** — a line boundary that no amount of widening the single-line class could reach, and safe for the opposite reason: the heading must be *bare*, so `Prior verdict: APPROVED` and `## r2 verdict: APPROVED` cannot get in. ⛔ **No readable/total ratio is quoted here, deliberately.** That figure was restated in four places and was wrong in every revision — the denominator moves whenever a review file is committed, including the QA reports that review this predicate, so the last version was already false at the commit that wrote it. **Derive it** from `git ls-files docs/reviews` (`.claude/rules/live-facts-measure-dont-quote.md`); the method is in the predicate’s own comment. What is stable is the SHAPES: decoration either side of the colon and a bare `## Verdict` heading are read; a blockquoted or struck-through verdict is refused on purpose; words on the label line and a verdict separated from its heading by prose are refused and FILED (`FUP-REGISTER-GATE-HYGIENE-VERDICT-SHAPES`). ⛔ A bound is a claim about a *population* — measure it per shape, never assert it from the shape you happened to look at. (2) A ninth ratchet, **`archiveMissingClosesWhen`**, counts archived follow-up **ids** whose entry carries no column-0 `**Closes when:**`, so a closure that drops the field reds while ⚠ retrofitting the historical ones is explicitly *not* required. ⛔ Its first cut was bounded by a **syntax** (`^### `) rather than the property and was blind to entries at `##`/`####` — one of which was a live instance of the very defect; re-derived over every heading level by classifying the lead-in between the hashes and the id, cap 108 → **121**, which is a truer number and not a regression. ⚠ BOUNDED, STATED: a ratchet bounds the *population*, not each closure, so retrofitting an old entry in the same commit that drops a new one keeps the total flat. (3) The branch check for an `in_progress` hub **could never pass on Windows**: the branch list went through a shell string, and `cmd.exe` keeps the single quotes in `--format='%(refname:short)'`, so every branch arrived as `'main'` and `.includes()` was always false. ⭐ Those quotes were themselves the fix for `/bin/sh` on macOS, where the bare `(` opened a subshell — *the same check, the same message, the opposite platform*, which is why it is now built shell-free from an argv array. It had never fired because there were no `in_progress` hubs: a check with zero live subjects.

- **`lint:config-schemas`** (`check-supabase-config-schemas.mjs`) — schema `app` holds 526 functions, 236 of them `anon`-executable, and the ONLY thing keeping those grants inert is that the `[api].schemas` list in `supabase/config.toml` does not name `app`; add it and all 236 become directly `anon`-callable over PostgREST in the same edit, with no other change anywhere. ⛔ BOTH FIGURES ARE LIVE COUNTS AND CARRY THEIR PREDICATE AND DATE, because nothing gates this file: measured 2026-09-08 on a fresh `supabase db reset` at head `20261003007350` (524 migrations — the pair, per R19), 526 = `pg_proc` rows in `app` with `prokind = 'f'`, and 236 = of those, `has_function_privilege('anon', p.oid, 'EXECUTE')`, run as its own query. ⭐ SUPERSEDED, quoted: this read *"467 functions, 237 of them `anon`-executable"* from a 2026-08-22 snapshot — +59 functions had landed since, and the `anon`-executable set fell by one when AE4.7b (`20261003007210`) revoked the PUBLIC grant on `app.is_staff_admin_of`. ⛔ Do NOT infer this 236 from `320` §U1's 236: §U1 pins the ACL-SHAPED set, this is the EFFECTIVE set, they coincide today by measurement and are provably able to disagree (ruling R26). Six in-tree documents argue their own severity from that line — including `supabase/tests/320_act_expiry_and_acl_hardening.sql` §U1, a LIVE assertion whose defence-in-depth calibration cites it verbatim — and until this gate **nothing in the tree noticed if it changed**: the only two programmatic readers of `config.toml` match `project_id` only. Trap, load-bearing in two directions: (a) ⛔ **the gate proves the FILE, never the DEPLOYED PostgREST configuration**, which is set outside this repo and can diverge with no commit, and no behavioural test anywhere asserts `app.*` is unreachable over the API (an e2e `rpc/member_can` probe was deliberately removed for silently 404-ing) — it is a PROXY for reachability, not the property, filed as `FUP-AUTHZ-NO-BEHAVIOURAL-PROOF-APP-SCHEMA-UNREACHABLE-OVER-POSTGREST`; (b) it has **two deliberately distinct failure texts** — `app` appearing is a SECURITY event whose message names the 236-function consequence **on its headline** (and escalates over any structural finding in the same edit, so `app` added together with a deleted sentinel still reds as the security event rather than as a formatting complaint), any other change is a REVIEW event ("this list is pinned; a new exposure needs a note"), and a reader meeting the red must be able to tell which from one line. It also refuses rather than guesses: a multi-line array reds as unreadable instead of parsing the first line and passing, and finding **zero or two** `schemas` assignments reds exactly like a wrong value, because a gate that found nothing must not pass. ⚠ Its self-test mutates the real file into `os.tmpdir()` (plants never touch the tree) and its fixture baseline is that file **canonicalised** — measured, not theorised: deriving the fixtures from the raw file meant a planted `"app"` poisoned every one of them, so the run exited **2 (checker broken)** instead of **1 (security event)**, hiding the one red this gate exists for behind a verdict about the instrument. The self-test asks whether the CHECKER can fail; the scan asks whether the FILE is pinned; conflating them loses the second. ⚠ CRLF is normalised before anything else, and that is not hypothetical either: `git ls-files --eol supabase/config.toml` reports `i/lf w/crlf`, so the working tree this gate reads is CRLF while the index is LF — with `.gitattributes` saying `eol=lf`, `git check-attr` agreeing and `git status` clean. When it reds: treat N1 as a decision to escalate (a PO ruling with an ACL programme attached), never a config edit to wave through; ⛔ never edit the pin alone, which converts a decision into a silent baseline.

- **`lint:budget-anchor`** (`check-budget-anchor.mjs`) — the `authenticated`-executable SECURITY DEFINER population of `app` + `public` is a **budget**: it falls only by a revoke and none has ever been executed on this tree, so it rises silently, one convenient `grant execute … to authenticated` at a time, each individually defensible. It rose **seven over its ceiling between 2026-08-27 and 2026-09-03 with no gate record naming any of them**, and the PO moved the ceiling 752 → 759 by ruling on 2026-09-08 only after all seven were attributed function by function. The live count needs a database, so the ratchet itself is pgTAP (`supabase/tests/320_act_expiry_and_acl_hardening.sql` §U4, with §U5/§U6 as its rising and falling controls) under `npm run test:db`; **this gate is the other half** — it holds the ceiling to ONE HOME (`docs/backend-state/authorization-and-audit.md` § Privilege budget, an anchor comment plus the prose sentence, which must agree with each other) and reds if `320`'s pinned literals ever drift from it. That split is what answers `ARM=census`'s standing prohibition against *"a number a banner states about a population NOTHING re-derives"*: the population figure is re-derived every pgTAP run, the committed number is a PO decision rather than a description, and the decision has one home with every copy gated. Remove this gate and §U4 inherits that prohibition in full. Trap, in three directions: (a) ⛔ **it compares two committed TEXTS and can never observe the live population** — it buys "the doc and the pin cannot drift apart between commits", not "the budget is 759"; the follow-up's ⭐ asked for a `lint:*` step that would notice the next commit, and that ⭐ is recorded as **amended by measurement**, never as delivered; (b) the mirror is read from the **actual pgTAP literal** (`  326,  -- BUDGET-ANCHOR app`), never from a comment restating it, because two comments can agree while the `is()` literal says something else — a mirror that mirrors nothing; (c) its ceiling check is `total <= ceiling`, deliberately **one-directional and silent on a fall**, with a good fixture (G3, ceiling 800 over a total of 759) proving it does not quietly demand equality — the falling case is carried by `320` **§U4**, whose `is(pg_temp.budget(…), 326)` / `433` / `759` pins are ABSOLUTE and therefore red in both directions; two instruments, two polarities, stated rather than inherited. ⚠ **CORRECTED 2026-09-08 (Batch 7 fix loop 4), and the superseded clause is quoted rather than overwritten:** this read *"the falling half is `320` §U6, which is exact-equality and reds either way"*. That was TRUE when written (`5602830d`) — §U6c then asserted *"the budget fell 760 → 759"* against committed literals, verified at `c84dd823^`. Ruling **R35** (`c84dd823`) re-expressed every §U5/§U6 assertion as a **delta from a baseline table snapshotted ONCE from the live catalog at the top of the same transaction, which `pg_temp.base()` then reads back** (⚠ **one word corrected 2026-09-08, QA rereview-2 N1**: this said `pg_temp.base()` *"re-derives from the live catalog"* — it does not, and a version that did would be **vacuous**, which `320`'s own comment says in terms: a re-querying baseline *"would move WITH every probe below and make every delta trivially 0"*. The correction is not cosmetic — it is the difference between describing a control and describing a control that cannot fail), so a real fall to 758 would snapshot 758 and leave **every §U6 delta holding**; §U6 is now a *control* proving the detector can move down, not the assertion that observes a fall. ⛔ Nothing was ever unprotected and this was never a red gate — §U4's absolute pins covered the falling direction before R35 and after it. What broke is the **attribution**, and R11 exists precisely so the polarity is *"stated rather than inherited"*: stated wrongly is the same defect wearing the fix's clothes. ⭐ `1956e7bd` edited this file **after** `c84dd823` and did not catch it — which is what *"Nothing gates this file"* costs in practice: a property moved from one assertion to another and the only record of which one holds it is this sentence. ⚠ Its self-test mutates the real pair into `os.tmpdir()` (plants never touch the tree) from a **canonicalised** baseline, for the reason gate 14 measured: fixtures derived raw are poisoned by the very plant they exist to detect, which inverts the exit code from 1 (the finding) to 2 (the checker is broken). Verified here on the real files: a planted mirror drift, a planted over-ceiling and a planted home-disagrees-with-itself each exited **1** with the baseline line reading *"the real files CANONICALISED — the bytes on disk are NOT clean"*, while three separate neuterings of the checker's own arms each exited **2**. When it reds: ⛔ **never edit `CEILING` to match a risen count.** The merge rule reserves that to the PO — diff the `authenticated`-executable DEFINER **set** (a count of +1 is equally consistent with 4 added and 3 removed), name each new member and the migration that granted it, and take the aggregate to the PO with the ruling recorded beside the edit. An edited ceiling with no ruling next to it is indistinguishable from the thing `FUP-PRIVILEGE-BUDGET-CEILING-BREACHED-BY-SEVEN` exists to forbid: converting a breach into a baseline.
