# AUTHZ Door-Blindness Audit — Findings

AUDIT-DOOR-BLINDNESS P0 (ADR 0078 §7.14). Generated by
`supabase/tests/mutation/p0-authz-door-audit.sh`. Method: neutralize each authz
gate (open it so it grants/allows regardless), run the FULL pgTAP suite, read
`Result:`. **COVERED** = suite went `FAIL` (a keystone asserts through the gate).
**BLIND** = suite stayed `PASS` (no keystone exercises it — a work-list item).
**ERROR** = run shape != baseline (harness bug: fix the neutralization, not a result).
**NOTICED** = run shape != baseline **AND** the suite went `FAIL` (§7.15c): a keystone
reddened, but a file ABORTED so the denominator moved and the failing assertions cannot
be attributed to THIS gate. ⛔ It is coverage EVIDENCE, **NOT A VERDICT** — strictly less
than COVERED and never a pass. **DISCLOSED, NON-BLOCKING** (PO ruling 2026-09-07): its own
class, quoted in every gate record that cites this sweep, and a run whose only impurity is
NOTICED exits **0 with the disclosure printed**. ⛔ BLIND still blocks the phase; ERROR is
still not a pass. The remedy is capture-then-assert, work-listed under
`FUP-C2-TIER1-VALUE-ASSERTIONS-ABORT-ON-AN-INLINE-RAISE`.

Baseline: Files=262, Tests=8876, Result: PASS.
Policies swept: 226 (real qual). Policies skipped (qual=true, vacuous): 10.
