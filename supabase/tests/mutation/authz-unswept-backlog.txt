# authz-unswept-backlog.txt — the CENSUS backlog for ARM 3 of the AUDIT-DOOR-BLINDNESS
# invariant (ADR 0079 Amendment 2). One live authz gate per line, keyed EXACTLY as the
# neutralization sweeps emit it:
#   * predicate/guard : app.<fn>(<identity args>)   e.g. app.member_can(p_commission_id uuid, p_capability text)
#   * RLS policy      : <table>.<polname> (<CMD>)   e.g. case_events.case_events_writer_insert (INSERT)
#
# CONTRACT (enforced by p0-authz-invariant.sh ARM 3 — `ARM=census`):
#   every `prosecdef` boolean function in app/public and every RLS policy in the LIVE
#   catalog MUST appear either in a committed findings md (any verdict — BLIND, COVERED,
#   ERROR, SKIPPED) or in THIS file. A gate in NEITHER has never been through a
#   neutralization sweep at all, so no verdict about it exists in any direction.
#
# WHY THIS FILE IS NOT authz-blind-allowlist.txt. That file's contract is
# "BLIND ⊆ allowlist" — every line means *we swept it and no keystone noticed*. These
# lines mean the opposite: *we have never swept it, so we do not know*. Merging them
# would let an entry here silence a genuine BLIND finding later.
#
# ⚠ UNSWEPT is NOT a synonym for BLIND. Several entries below are probably COVERED
# already; nobody has asked.
#
# ── Why 46 gates were unswept on 2026-08-04 (the root cause, not 46 oversights) ──
# The two sweeps enumerate DIFFERENT, and both INCOMPLETE, domains:
#   * p0-authz-door-audit.sh policy arm queries the live catalog but filters
#     `polcmd in ('r','*')` — it audits SELECT and ALL policies only. Every INSERT /
#     UPDATE / DELETE policy is out of its domain by construction.
#   * p0-authz-writepath-audit.sh covers those, but from a 33-row EMBEDDED SNAPSHOT
#     captured 2026-07-18 and a 7-name hardcoded guard list. The snapshot never grew.
#   * the door audit's predicate arm filters on a NAME PREFIX
#     (`^(is_|can_|has_|…)`), so `capa_viewer_can_manage`, `interview_viewer_can_write`,
#     `rca_writer_can_write`, `member_can` and `confidentiality_clearance_ok` are all
#     real authz gates that no sweep has ever had in its worklist.
# So a write policy or an off-convention gate could be added on any day and be invisible
# to BOTH sweeps AND to ARM 1 — which compares BLIND to the allowlist, and a gate that
# was never swept is in neither set. That is the hole ARM 3 closes.
#
# Two of these are the SAME 2026-07-27 out-of-phase ETH hotfix as the FUP-AUTHZ-2
# fifteen (`answers_*_targeted`, `responses_update_targeted`): the hotfix's SELECT/ALL
# policies showed up as BLIND, its write policies did not show up at all.
#
# BURN-DOWN: sweep an entry (diff-scoped ARM 1 recipe, ADR 0079 Amendment 1), then
# DELETE its line here in the same commit — its verdict now lives in the findings md.
