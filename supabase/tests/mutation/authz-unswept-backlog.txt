# authz-unswept-backlog.txt — the CENSUS backlog for ARM 3 of the AUDIT-DOOR-BLINDNESS
# invariant (ADR 0079 Amendment 3). One live authz gate per line, keyed EXACTLY as the
# neutralization sweeps emit it:
#   * predicate/guard : app.<fn>(<identity args>)   e.g. app.member_can(p_commission_id uuid, p_capability text)
#   * RLS policy      : <table>.<polname> (<CMD>)   e.g. case_events.case_events_writer_insert (INSERT)
#
# CONTRACT (enforced by p0-authz-invariant.sh ARM 3 — `ARM=census`):
#   every `prosecdef` boolean function in app/public and every RLS policy in the LIVE
#   catalog MUST appear either in a committed findings md (any verdict — BLIND, COVERED,
#   ERROR, SKIPPED) or in THIS file. A gate in NEITHER has never been through a
#   neutralization sweep at all, so no verdict about it exists in any direction.
#
# WHY THIS FILE IS NOT authz-blind-allowlist.txt. That file's contract is
# "BLIND ⊆ allowlist" — every line means *we swept it and no keystone noticed*. These
# lines mean the opposite: *we have never swept it, so we do not know*. Merging them
# would let an entry here silence a genuine BLIND finding later.
#
# ⚠ UNSWEPT is NOT a synonym for BLIND. Several entries below are probably COVERED
# already; nobody has asked.
#
# ⛔ WHAT ARM 3 STILL CANNOT SEE — stated here because a census that looks complete is
# more dangerous than one that admits its edge. The domain is: `prosecdef` booleans,
# `prosecdef` row-returning doors, and RLS policies. It does NOT cover
# **AUDIT-INVOKER-WRAPPER** (PROGRESS.md, Remaining pre-pilot work #3): a `prosecdef = f`
# INVOKER function whose own hand-written `if not exists (…)` probe is the only gate in
# front of an `app.` DEFINER body. Those carry no `prosecdef` flag and no policy, so
# nothing in this file's domain reaches them — and **130 of 281 `app` DEFINER functions
# carry EXECUTE to PUBLIC**, which makes the wrapper the whole boundary each time.
# Proven live in FF-3: deleting `get_response_validation_errors`'s existence probe reds
# ZERO assertions across six files while a commission-Y staff reads commission-X rule
# messages and item labels. Scheduling is a PO decision; the point of this note is that
# ARM 3 holding is not evidence about that class.
#
# ⛔ SECOND EDGE, MEASURED 2026-08-13 (DM3) — **DEFINER doors that return a COMPOSITE**.
# The domain's function clauses are bounded by RETURN TYPE: `bool`, or `proretset` +
# authenticated-EXECUTE. A `prosecdef` door that returns ONE composite row
# (`returns public.<table>`) is in NEITHER, so it is invisible to ARM 3 — and to every
# other arm, all of which bound themselves the same way. This is ADR 0118 §12's standing
# finding ("a sweep boundary drawn on a return-type SYNTAX cannot enforce a PROPERTY"),
# now with a number on it:
#
#     136  prosecdef boolean                      IN the domain
#      49  prosecdef proretset, auth-reachable    IN the domain
#      88  public INVOKER plpgsql, auth-reachable IN the domain
#    ▸146  prosecdef COMPOSITE-returning,
#          auth-reachable                         NOT in the domain
#
# 146 is not a DM3 regression — the class predates it — but DM3 ADDED one to it, and the
# honest place to say so is here rather than in a findings md, because no sweep has been
# run over any of them and a verdict nobody earned is worse than an admitted gap:
#
#     public.attach_controlled_document_version_file(p_version_id uuid,
#       p_core_version_id uuid, p_summary_of_changes_md text, p_expiry_date date)
#         → DEFINER, `returns public.controlled_document_versions`, EXECUTE to
#           authenticated, and in `public` so PostgREST can reach it. Its own
#           `app.is_staff_admin_of(v_commission)` check IS the entire boundary
#           (it replaced `set_document_version_file`, which was in the same class).
#           Behaviourally pinned by pgTAP 330 DM3·P1/P1b/P1c and by 314 §10.3's
#           mutation case — but by keystones, NOT by any authz arm.
#
# DM3's other new functions are recorded here for completeness and are NOT of this class:
#   app.controlled_version_source_path(p_version_id uuid) → DEFINER returning text, no
#     authority check of its own (a resolver called by gated doors). Reachable only from
#     `app`, which config.toml does not expose to PostgREST.
#   app.guard_controlled_core_binding() / app.guard_ethics_document_case_scope() /
#     app.mint_controlled_document_resource() → DEFINER TRIGGER functions; not callable
#     as gates, PUBLIC-revoked.
#   app.assert_documents_wave_b_enabled() → INVOKER, but in `app`, and the INVOKER census

# helper:  — NOT AN AUTHZ GATE. Introduced 2026-08-18 (ADR 0125/0126 print build).
#
# `ARM=census` enumerates every `prosecdef` boolean function, which necessarily
# catches DERIVATIONS as well as PERMISSIONS. A derivation has no authorization
# decision to neutralize: there is no gate to open, so "BLIND" is not a verdict it
# can receive. Listing them bare would misfile them as unswept authz; omitting them
# re-flags them on every census forever.
#
# A `helper:` line asserts TWO things, and both must be true when it is added:
#   1. the body references NO authz predicate (no can_*/is_*/has_* authorization
#      call) — verify from `prosrc` in the LIVE catalog, not from the name;
#   2. its BEHAVIOUR is pinned by a named suite, and that pin has been DRILLED
#      (neutralize → observe RED) with the drill recorded.
# ⚠ If a helper later acquires an authz call it STOPS being a helper and must move
#   into a findings md. The census cannot detect that transition — the reviewer must.
# ─────────────────────────────────────────────────────────────────────────────
