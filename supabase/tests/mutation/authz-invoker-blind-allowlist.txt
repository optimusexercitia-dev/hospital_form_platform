# authz-invoker-blind-allowlist.txt — the standing BLIND allowlist for ARM 5,
# AUDIT-INVOKER-WRAPPER (ADR 0078 §7.14 / ADR 0079). One wrapper per line, keyed EXACTLY
# as p0-authz-invoker-audit.sh emits it (the `gate / policy` column of
# docs/reviews/authz-invoker-audit-findings.md):
#   public.<fn>(<identity args>)   e.g. public.get_response_validation_errors(p_response_id uuid)
#
# WHY A SEPARATE FILE FROM authz-blind-allowlist.txt. That file's contract is "the union
# of the three prosecdef sweeps' BLIND sets ⊆ this file". Folding a fourth, differently
# bounded domain into it would mean a stale entry in one domain could mask a new finding
# in another, and ARM 1's stale-entry hygiene note would start firing on wrappers it
# never sweeps. One allowlist per sweep domain keeps both subset checks exact.
#
# CONTRACT (enforced by supabase/tests/mutation/p0-authz-invariant.sh ARM 5):
#   the invoker sweep's BLIND set MUST be a SUBSET of this file. A BLIND that is NOT
#   listed here fails the gate (non-zero exit) — a NEW un-keystoned invoker wrapper.
#   Either add a mutation-proven keystone (preferred) or, if it is a genuine backstop,
#   add it here WITH justification in the same commit.
#
# ⚠ THIS IS A TRACKED BACKLOG, NOT A SILENT CAP. Every line is a wrapper whose own gate
# no keystone exercises — which for this class means the gate is the WHOLE boundary,
# because the `app` DEFINER helper behind it bypasses RLS by construction. A line here
# is a debt with a name, not a dismissal.
#
# ⚠ NEVER allowlist a tenant-isolation gate. The standing rule from ADR 0079: allowlist
# only an unreachable backstop. If opening a wrapper lets one commission read another's
# rows, it gets a keystone, not a line in this file.

# ─────────────────────────────────────────────────────────────────────────────────────
# Seeded 2026-08-12 from the first full invoker sweep (ADR 0079 Amendment 7). Run detail:
# docs/reviews/authz-invoker-audit-findings.md.
#
# EVERY line below is BACKSTOPPED BY RLS, not merely un-keystoned, and the justification
# is the same one in three shapes: for an INVOKER function the write still runs under
# RLS, and here the target table's write policy carries the SAME identity predicate the
# wrapper's gate does. Opening the wrapper therefore changes nothing a caller can reach —
# which is why the suite stays green, and why forcing a keystone would be asserting on a
# redundant layer rather than on a boundary.
#
#   FAMILY A — commission vocabulary (case tags / outcomes / narrative types / meeting
#   types / member titles / phase results / template outcomes / meeting settings / case
#   narratives). Gate: `is_staff_admin_of(c) OR is_tenancy_admin_of(c)`. Policy, e.g.
#   `case_tags_staff_admin_write (ALL)`:
#       (app.is_staff_admin_of(commission_id) OR app.is_tenancy_admin_of(commission_id))
#   — character-for-character the wrapper's own condition.
#
#   FAMILY B — meeting CHILDREN (agenda items, attendees, case links). Gate:
#   `app.assert_meeting_staff_admin`, whose body is
#   `app.is_staff_admin_of(app.commission_of_meeting(p_meeting_id))`. Policies, e.g.
#   `meeting_agenda_items_staff_admin_update`:
#       app.is_staff_admin_of(app.commission_of_meeting(meeting_id))
#   — the same predicate, resolved one level deeper. ⚠ Resolve the assert's BODY before
#   reusing this justification; the wrapper text alone does not show the predicate.
#
#   FAMILY C — repeating-group instances. Gate: `app.assert_group_writable`, which its
#   own comment states is "the UNION of the response_group_instances write policies …
#   Mirrors the policy rather than restating half of it". Verified against
#   `response_group_instances_write_own_draft` + `_write_targeted`.
#
#   FAMILY D — case / template phases (add_ad_hoc_phase, add_template_phase,
#   remove_template_phase, update_template_phase). ⚠ These are here for a DIFFERENT
#   reason and the distinction matters: they carry NO wrapper-level identity gate at all.
#   RLS is the sole boundary and is correct —
#       case_phases_staff_admin_write:
#         is_staff_admin_of(commission_of_case(case_id)) AND NOT is_case_excluded(…)
#       process_template_phases_staff_admin_write:
#         is_staff_admin_of(commission_of_template_version(tvid))
#           OR is_tenancy_admin_of(commission_of_template_version(tvid))
#   — so there is nothing for a wrapper keystone to defend. Their BLIND verdicts are the
#   `g1-only` PROVISIONAL kind: what the sweep opened was a DOMAIN probe (is this form
#   part of this template?), not an authorization decision. Hand-classified here rather
#   than trusted, which is exactly what the PROVISIONAL flag exists to force.
#
# ⛔ NOT ALLOWLISTED, DELIBERATELY: the meetings-TABLE verbs (cancel / distribute /
# update_minutes / set_quorum_met, and update_meeting). There the wrapper is STRICTER
# than the policy — `meetings` RLS also admits `member_can(c,'schedule_meetings')` — so
# the gate is the sole boundary between a staff_admin and an ADR-0061 delegate. Proven by
# mutation, not argued: with the gate opened a `schedule_meetings` holder cancelled a
# meeting. They are keystoned by supabase/tests/327_invoker_wrapper_meeting_authority.sql.
# If a future change makes one of them BLIND again, keystone it — do not add it here.
